# 依据运行反馈修复输入并继续求解

用户要求完成计算时，授权包含任务范围内的输入卡修复与必要重算。默认不设真实 OFFBEAT 启动次数上限；次数保留统计。只有用户明确设置限制时才采用，不自行添加两次、三次之类的限额。仅准备或仅提取任务仍不启动求解器。

## 恢复闭环

1. 公共执行器返回失败时，先消费 `diagnostic` 中的原生错误摘要；不足才读取对应日志片段和相关输入。检查退出码、正常结束和实际目录，不把已有终态文件当成功。
2. 从日志给出的缺失项、合法类型、报错边界和本地使用契约形成具体修复。源中的相关选择器和依赖一起检查；不能把通用词语直接当软件支持的值，也不因关闭一个物理模块而一并关闭其他边界需要的模型。
3. 在新独立尝试目录重建输入，复用已有准备脚本和用户参数，批量修正本次错误关联项并回读；保留前次输入、日志、状态和失败凭据。新尝试不继承失败执行凭据。状态可能被失败运行改写，新的初态/检查点从原始准备输入或可信保存状态取得，不盲目复制失败结果作为新鲜初态。
4. 通过同一公共执行器重新运行，验证实际终态与用户要求。再次发现可修复错误时继续闭环，不因此前失败次数而提前交付。
5. 成功的工况与提取直接复用。多工况将修复应用到受影响的未完成点，保留原始物理参数身份与独立尝试身份；不要重算无关成功点、重新抽样或改变搜索方法。

每次修复记录错误证据、修改项及理由、回读、前后尝试关系和新运行状态。已有任务记录即可，不要求另建复杂框架。没有专用参数契约的任务继续一般输入工作流；使用运行反馈补足局部语法和依赖，不要求先覆盖全部组合。

## 何时停止

- 正常完成且请求响应齐全：停止求解并交付。
- 用户要求停止，或达到用户明确设置的限制：按要求保留与交接。
- 环境、软件或必要数据缺失，已确认无法用允许的输入修复继续：交付具体阻塞证据，不能伪装完成。

同一失败反复出现时，重新核对修复假设及关联输入；没有输入、配方或重启状态变化时不原样重复启动。次数不限仍须取得新信息或落实具体修正。运行反馈允许新一轮诊断，不授权读取或修改求解器、插件、解析器和生成器实现，也不授权安装或编译。

公共执行器对同目录调用保持幂等，重复调用会返回原凭据。此行为防止意外重复启动；有修复后应使用新的尝试目录继续，而不是删除失败凭据。`Study.run` 也保留失败记录；使用新尝试身份接入修复后的点，明确对应原参数点。
