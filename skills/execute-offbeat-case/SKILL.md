# 执行一个已准备算例

先加载本任务所需技能，再一次读取相关输入与配方。任务全程离线，只用准备的本地资料和软件。默认工作是构建输入卡并计算。OpenFOAM 环境、OFFBEAT 入口和 Python 已由启动器准备；直接使用，不做安装位置、版本、动态库、二进制或源码目录探测。输入已确认时立即进入公共执行器。你是运行助手，禁止查看或修改求解器、插件、生成器和解析器实现；环境报错保留日志并报告缺口，不自行安装、编译或源码排查。

## 已准备的参数计划

Prepare 命中已验证参数契约时，复用其[参数计划入口](../prepare-offbeat-case/references/parameter-plan.md)的 `run` 一次完成准备、公共执行和实际场核对。不要另写同等控制脚本或重复启动。运行结果 `status=verified` 才证明该契约生效；`input_readback_only` 只说明输入回读。长调用从首次提交就用 `run_in_background: true`，统计实际 OFFBEAT 启动并保留失败证据，默认无次数上限。

## `case` 类的必经工作流

单个算例的运行、物理续算或运行状态检查命中本类；多个时间步或输出量仍为一次评价。多次评价由 Conduct 统一调度本执行器，已有结果的纯分析归 Extract。其他未覆盖任务不继承本工作流。

1. **接收准备**：请求运行时复用输入与回读；缺少准备必须加载 Prepare 完成相应阶段，不能用试跑替代输入确认。只检查已有运行状态时跳过准备。
2. **确定模式**：只检查状态时调用 `inspect_case`，不启动求解；请求运行时确认实际执行配方、当前进程或凭据，以及用户是否明确设置限制；未设置则不限制启动次数。
3. **执行并等待**：通过下述公共执行器运行并等待原生作业终态，不复制另一套进程与状态管理。已经有进程或终态记录时复用，不重复启动。
4. **核对终态**：保存执行凭据，分别报告正常完成、失败或未完成。存在最终场本身不能通过本阶段。
5. **按需提取**：用户要求物理响应时必须加载 Extract，使用已确认结果根。提取或报告失败只修复该阶段，不重新求解。

正常执行到请求终点并保留证据，才算求解完成；只检查模式以真实状态检查记录为交付。发现可修复输入错误必须继续修改并重算；真正阻塞才交付诊断和未完成项，不能宣布求解成功。

### 修复输入后继续求解

求解失败时必须按[输入恢复闭环](references/input-recovery.md)处理：先读执行器 `diagnostic` 的原生错误摘要，再定点读卡；按错误、合法类型和本地契约修复，在新尝试目录回读并重新运行，直到正常完成或确认真实阻塞。未见过的输入组合可以通过运行反馈发现问题，不要求先有专用配方。默认不限启动次数，不因已经失败两次或三次而停止。没有实质修正时先重新诊断，禁止原样循环。

### 物理续算与中断恢复

需要固定步长或真实续算时，直接使用[本地时间与续算配方](references/time-and-restart.md)。它给出本机支持的控制项和分支交接步骤，不用搜索网页、源码或重启示例。

重复调用公共执行器只会复用已保存终态，不会自动从最新时间推进。用户要求改变终点或从保留场续算时，准备独立目标，保留原始输入、结果和失败凭据，明确选择起点、载荷覆盖与新终点。复制所需输入和起始场，确认执行配方不会清理续算状态；目标不继承旧 `.mandifuel-execution.json` 作为新尝试凭据，旧凭据在原任务原样保留。再通过公共执行器建立新尝试，保留实际启动计数。仅恢复监控、提取或报告时不建立新求解。

## 使用公共执行器

读取源算例实际的计算配方一次，沿用其中必需的预处理，不附加用户未要求的解析对照、绘图或清理。公共执行器在算例目录运行配方并等待结束。预计较长的求解、控制器或提取命令首次就通过 Bash 的 `run_in_background: true` 提交，再用原生作业句柄等待；前台超时是终止，不是自动转后台。下面是交给 Bash 的实际命令：

```bash
python3 "$MANDIFUEL_PLUGIN_ROOT/skills/execute-offbeat-case/scripts/case_runner.py" run --case ./case -- bash run.sh
```

Python 可从 `scripts/case_runner.py` 导入 `run_case(case, *, command=['bash', 'run.sh'], log='log.offbeat', end_time=None, timeout=None)` 或 `inspect_case(case, *, log='log.offbeat', end_time=None, exit_code=None)`，无需读取执行器实现。两者返回下述状态字典；`inspect_case` 不启动程序。多工况回调默认由共享 Study 调用本执行器，避免在模型轮次之间分别启动各点。

`command` 使用源配方的实际文件名；源只有 `Allrun` 时使用 `['bash', 'Allrun']` 或保持其预处理顺序的任务包装。复制源时跟随需要保留的软链，或在目标中解析它们。不要凭文件名假定根目录模型输入可以省略。

若包装脚本重新加载 OpenFOAM `bashrc`，在 source 前关闭 `nounset`，结束后恢复自身设置，并保留配置的 OFFBEAT 二进制目录在 `PATH`。无界面绘图使用可用的后端，例如 `Agg`。shell 管道要传播求解器失败，避免 `tee` 的成功掩盖非零退出。

## 启动前的相关检查

复用 Prepare 已保存的[软件能力与已知问题检查](../prepare-offbeat-case/references/software-capabilities.md)，只处理本题修改及直接依赖。已知错误先修卡，未知范围继续一般输入流程和运行反馈；不把表当完整白名单，也不重复安装或全目录检查。

只核对本题输入：用户要求的改动已回读、执行配方不清理所需起始场、载荷表覆盖请求时段、用户明确限制仍允许（默认不设次数上限）。不要检查 Time、userTime、材料模型等源码来证明常规输入能够运行。已有明确末点插值兼容说明时，只处理对应载荷表；不为了预防假想故障改变载荷或增加试跑。

只处理实际阻止本题运行或必需响应的后处理输入错误。未影响请求结果的探针警告不触发额外适配，不检查 patchProbes/probes 源码或动态库。必要的采样修正采用本地已说明的输入写法；说明不足时报告该响应不可用。

## 终态与完成标准

标准瞬态循环的有效终点受 `controlDict.endTime` 与热源最后时间标记共同约束。自适应步长会向终点对齐，正常循环结束调用 `writeNow()`，因此终态提取使用执行器确认的终态目录，不要求额外修改周期写出。

执行器返回 `status`、绝对 `result_root`、`end_time`、`final_time`、`times`、`exit_code`、`terminal_marker`、`solver_seconds`、`solver_steps` 和 `wall_seconds`。正常完成结合成功退出、正常终止标记和实际到达请求终点的目录判断；终止词 `end` 不区分大小写。执行器在时间值尺度的 `1e-12` 范围识别累加舍入误差，并将容差限制在已知时间步或已保存时刻间距的1%以内；`time_match` 给出判定方法和容差。它不会把明显少算或真实失败改为成功。

终态提取传入返回的 **`final_time` 实际目录名**，不要再用请求的十进制文本精确匹配。例如请求 `17735.41` 天，实际目录 `17735.410000000229` 可正常完成；日志只显示 `17735.4` 也不说明少算。不要为目录名外观或日志显示位数修改 `timePrecision` 后重新求解。

| 情况 | 处理 |
|---|---|
| `status == 'completed'` | 复用该记录，交给提取或研究历史 |
| 非零退出、缺少终止证据或未到终点 | 保留失败或未完成状态，定位日志 |
| 失败但存在 `1/T` 等场 | 可标记为诊断数据；不改成成功，不作为正常 `adopt` |
| 正常求解后提取/报告失败 | 使用同一结果根修复，不启动求解器 |

执行器保留 `.mandifuel-execution.json`；重复调用会复用已保存的成功或失败记录，不自动重试。旧执行器仅因时间舍入误判、且退出码为0与正常终止证据完整时，可返回 `completion_reconciled=True` 的修正检查结果，原凭据不改写，也不启动求解。修复输入后的重试属于计算任务范围，使用独立目标和身份；仅在用户明确限制时遵守该限制，不能删除失败记录来强制重跑。

## 检查外部运行与时间单位

```bash
python3 "$MANDIFUEL_PLUGIN_ROOT/skills/execute-offbeat-case/scripts/case_runner.py" inspect --case ./case --exit-code 0
```

`inspect` 只读取已有证据。仅在确知进程退出码时传入 `--exit-code`。`--log`、`--end-time`、`--timeout` 调整对应参数；不要用它们掩盖真实失败。

使用 `controlDict.userTime` 时，完成检查采用结果目录的数值单位。例如3650天的终态目录是 `3650/`，不能用物理秒315360000去匹配；物理秒换算仅用于解释与分析。

`endTime`、`deltaT`、时间目录和探针时间按该模型时间解释。`seconds`、`hours`、`days` 对物理秒的倍率分别为1、3600、86400；直接读取本题 `controlDict.userTime`，不读取 Time 或 userTime 类实现。其他单位沿用算例已有明确约定，未核实时只限制该项换算结论。

默认不限制真实 OFFBEAT 启动次数；所有真实启动均记录，包括初始化失败和重试。时间步、保存的场、提取调用与帮助查询不是新的物理评价。
