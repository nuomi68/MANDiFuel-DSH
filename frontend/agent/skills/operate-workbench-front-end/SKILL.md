# 操作工作台前端

## 确定本轮范围

调用 `ui_inspect(target="page")` 查看浏览器连接、当前工况与时刻、物理场、两栏布局、已有组件及错误。工作提示中的 request 是本轮请求，calculationRequest 说明最近的计算目标。局部显示调整保留现有视图、字段、参数值、图表范围与页签。只有计算产物变化或用户要求重排时才重新审视整体布局。

工作提示中的 `requestKind=display-edit` 表示本轮只处理用户指定的显示变化。改色时读取 model.actualDisplay 的调色板并核对新回执即可。仅在新增、修改或专门检查工况与时刻联动时主动请求切换测试。页面已经符合要求时，直接核对回执并返回 unchanged，保留已有配置版本。

根据本轮所需证据读取参考，每项通过 `ui_read_skill(resource="references/文件名.md")` 加载。

| 本轮要解决的问题 | 观察和操作依据 |
| --- | --- |
| 选择模型、字段、参数或修改视角、颜色、探针 | 读取 model 和 settings。model 可按视图 ID 查看其 caseRoot、输入回读和已导出字段。真实输入进入模型参数抽屉；用户需要调节的显示量进入显示设置并建立实际绑定。[模型显示](references/rendering.md) · [布局和参数](references/layout.md) |
| 分析一个或多个算例 | 读取 data 索引，按文件名打开数据列与报告。核对实际成功工况、响应定义、单位、采样位置与聚合方法。抽样按实算点展示散布，优化展示有依据的目标与可行候选，瞬态按保存帧组织。多工况优先让用户看见输入和响应的关系；只有表、说明或图片合适时按实际需求选用。[数据与图表](references/data.md) |
| 解释关键结论或异常 | 读取 evidence，按 claim ID 查原始定义和来源。优先展示物理核查与失败项；相同终点回执可共用一个 evidence 组件并保留各算例入口。[核查依据](references/evidence.md) |
| 局部调整、跨栏移动或有新交付 | 读取有关的 main / aside 节点，按最新版本执行局部操作。模型和主图排在适合阅读的位置，次要表或说明可以放在聊天窗下方，相关图可用页签切换。清理被替代的面板。[插槽协议](references/slot-protocol.md) |

## 提交和验收

1. 用所读 revision 调用 `ui_apply`。后续事务可以使用成功回执的新版本；遇到冲突，先重新观察。导出字段时先提交模型，核实字段与算例后，再提交引用它的图表。调整已有显示参数值用 `update.parameterValues`。手动选场保留原生下拉框。标题流程进度与页尾等待占位由宿主管理。
2. 用 `ui_wait_for_render` 查看当前配置的浏览器回执和错误。新增或修改工况、保存帧联动时传 `verifySelection:true`，核实实际选择、模型变化与还原。浏览器未连接、用户中断操作或没有可操作的第二项时，如实区分。对于没有模型的纯表格或说明任务，验收对应内容即可。
3. 当提示含 comparisonReview 时核对比较图的输入与响应来自相关工况。抽样设计图可以保留，至少有一幅比较图应展示实算响应或跨工况物理剖面。用户明确限定格式时，结构化结果可附 `comparisonException:{kind:"requested-format",reason:"用户原话"}`。确实缺少可比口径时使用 `incomparable-data` 并写明缺项。

结束时返回 status 和一句用户能看懂的 summary，写明实际改变或仍缺的内容，可附已观察的 revision。已提交且显示获确认用 applied，原页面已经满足且获确认用 unchanged。配置已交付但待浏览器回执，或计算尚无所需数据，用 pending。仍有可交付的组件、事务需要修正或额度已用完，用 partial，注明下一步。当前数据或能力无法满足请求时用 blocked 并说明缺口。
