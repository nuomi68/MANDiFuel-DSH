# 操作工作台前端

从用户的当前要求出发选择内容与交互，不套固定页面，也不把最近的缩放、测点等例子当成功能边界。工具返回的组件目录、字段目录与权限是当前可用能力的依据。

## 观察后操作

先 `ui_inspect(target="page")` 查看实际布局、页签、筛选、当前物理场和参数。检查 composition、browser.nodes 的实际可见性、遮挡与交互状态，清理被新内容替代的旧节点，避免重复；设置抽屉遮挡和未选中的不同页签不代表冗余。按需读取 `main`、`aside`、`settings`、`model` 或 `data`；需要组件/渲染能力时读取 `capabilities`。没有浏览器连接时可以保存配置，但不能宣称已经显示。

用刚读取的 `revision` 提交 `ui_apply`。局部内容优先用节点插入、更新、移动或删除；整块重编排可替换插槽树。新增参数使用 settings upsert，结合 rendering.program 建立实际绑定。控件 ID 和组件树由你生成；主区、右侧、设置和模型执行器的边界由宿主管理。

导出新模型或增加字段时，先提交模型并检查实际字段，再编排引用它的图表；这样可选图表失败也不会阻断已经生效的物理场。切换页签、检索或图表缩放等直接用 interact 操作，不必为改变一次交互状态重建组件。

遇到版本冲突，重新读取状态再决定，不用旧快照覆盖手动调整。成功后使用 `ui_wait_for_render` 检查浏览器确认、组件错误及模型错误；最多针对同一问题修正两次，保留已经有效的部分。每轮最多 8 次修改、24 次工具调用。

修改模型显示方式、色标或参数时读取渲染参考，核对控件的选项、绑定、字段覆盖和浏览器实际状态；组件无报错不等于用户要求已实现。宿主会自动显示工作中与等待渲染的状态，不要自行生成假的进度条或遮住已有结果。

## 按需读取参考

通过 `ui_read_skill(resource=...)` 读取对应文件：

- [插槽与工具协议](references/slot-protocol.md)：节点操作、并发版本、返回状态和完整显示更新。
- [组件与布局](references/layout.md)：页面编排、动态控件、左右空间与交互选择。
- [真实数据与字段](references/data.md)：数据源、字段分量、单位、工况归属及图表。
- [模型与显示程序](references/rendering.md)：显示变换、相机、色标、切片和标注。

单数值 metric 卡片不在可用目录中；不要改用独立 text 框绕过此约束。少量数值放入有标签、单位和对照的表格，或必要的结论段落。局部更新后复查整个当前页面，移除内容重复或已被替换的窗口。

物理场窗口是宿主保留区：从真实网格预览逐步升级为已有保存场。有结果时核验当前字段、真实映射及 browser.model 的可见性，完成时不能只剩图表或说明。网页未收到相应场时保留有效网格并如实说明，禁止重新求解来满足界面要求。

标题流程进度及计算子过程由独立观察器维护，不提交 progress。你工作的等待反馈由宿主末尾两个骨架窗口提供。

## 数据与边界

复用保存场和普通报告，保持真实单位、符号、缺失值及采样口径。确认使用的是用户需要的成功结果源，不把温度预览当作全部可用变量。显示重建必须有几何依据，并区分一维/二维解与显示几何。不能用修改几何外观来冒充重新计算。

主区、右侧与设置可自由组合已注册的组件和参数；模型插槽通过受限显示状态与数学表达式操作。聊天窗、应用导航及源码受保护。用户需要当前组件目录之外的交互或新算法时，说明能力缺口，不产生无效控件或虚构效果。
