# 组件与布局

界面原则：窗口固定叫“显示设置”，不要命名成“按用户需求生成的参数”，也不要解释 schema、配置或 agent 实现。默认保留少量基础功能（观察方向、线框、色标范围、已有视图切换），根据最新用户要求逐步补充便捷操作，并保留仍在使用的设置。功能组使用自然名称，例如“显示缩放”“点值标注”“切片”“温度色标”。不预列所有功能，不把缩放或点值当作仅有的需求。保留用户当前配色；用户只要求图表、视角或标注时不要重置 rendering 样式。

物理场选择框旁不追加模型类型、维度、缩放等说明。显示用途与比例在“显示设置”或必要的简短图注中说明。最大/最小值及极值位置是可选显示，默认关闭 extrema，不把极值标注或最大最小值指标当作每次渲染的必需项；仅用户明确要求或已主动开启时保留，用户取消后关闭，不能擅自恢复。提取或报告最大最小值，不代表用户要求在云图上标注它们。

观察方向仅提供自动、XY、XZ、YZ，不添加“三维/立体”选项或按钮；自动相机仍可观察真实三维模型。先把模型放在主区域上方，说明保持简短，不能用长篇说明代替缺少的物理场。模型节点放在未选中的页签、条件隐藏或被布局替代时，宿主会将原生窗口放回主区，保持网格/物理场可见。

生成式 UI 的布局规则：视角、网格、剖切、显示缩放、色标、测点参数等操作项默认归入悬浮的“显示设置”；主区域用于模型、图表、数据和必要结果说明。controls 组件默认 placement:"settings"，按 title 分组，并复用已声明控件，不在主区域复制一份。仅用户明确要求把操作项放在图旁时使用 placement:"inline"。这一规则适用于后续生成的任意操作组，不是只针对某几个标题。

text/caption 是静态文字，不要把可手动调整的缩放倍数、坐标或选择值写成“当前值”；实时值由控件、图例或程序标注显示，说明只写显示用途、单位与数据口径，避免用户调参后文案过期。

你现在可以编排页面，而不仅是填写固定参数面板。ui_inspect(capabilities).components 是可用组件目录，按目录输出 ui:{version:1,mode:"above"|"below"|"replace",root:组件树,datasets?:{数据ID:{file:"任务工作区内的真实JSON数据表"}}}。每个组件使用唯一字母开头 id、type、可选 title；row/column/grid/tabs 用 children，grid 可有 columns:1到4。mode replace 编排生成内容；宿主模型窗口仍保留，above/below 在模型前后增加面板；用户没要求改变布局时不发送 ui，不把当前配置清空。ui:null 恢复默认布局。不要把新能力一次全部放到页面。

图表必须按用户想分析的关系选择表达，不能全部套用同一种蓝色折线/散点图。默认页面不自动提供“单元场分布”；单元编号没有空间次序时不能当成物理剖面连线。只有用户需要真实空间/时间关系时才配置对应数据图。

二维/三维场的 source.kind profile 返回全部单元，按半径排序仍可能混合不同轴向截面，不能把它们全连成一条“径向温度曲线”。优先绑定已有报告中的固定截面采样表，并注明真实轴向位置与坐标单位；没有合适采样表时暂缓剖面线图，或明确使用空间散点，不伪装成单一截面。不要把有限元单元顺序、重复半径或材料间隙自动平滑成连续剖面。

网格、保存场或报告尚未出现时保留宿主模型窗口，等待真实交付，不发布引用不存在文件、字段或视图的面板，也不更新标题流程进度。有可用配置后尽量复用结构，只在数据或要求确实变化时增补。

根据 views.task.coordinateBounds 检查可读性。细长二维截面在物理比例下窄至难以辨认时，默认用 viewState.aspectMode:"fit" 显示，在“显示设置”的坐标比例选项中说明；这只改变显示比例，不变更几何数据和场值，也不要求默认出现 XYZ 缩放参数。用户要求等比例时使用 physical。不要让已有真场云图看起来像空白细线。

适配窗口已按所选两个坐标轴的真实跨度展开，通常保持额外的 scaleX/scaleY/scaleZ 为 1；不要再叠加按几何长宽比估算的径向放大，否则会把另一轴再次压成细条。正视平面按实际 coordinateBounds 的两个主要跨度选择，不凭“棒形”名称假定轴向。用户明确要求进一步缩放时再加入相应参数。

网页分析默认保留交互：悬停读数、图例开关、数值坐标缩放/复位、全屏查看由前端提供；source.kind study 自带真实 runId 联动。dataset 来自工况报告时，用 source.runId:"保存真实研究工况ID的列名" 显式关联，例如记录 id 与研究 run.id 确实一致时可用 runId:"id"。不能按行号、参数近似值或目录名猜关联；没有实际研究关联的数据仍可悬停、缩放和导出，不虚构模型入口。关联后，图点和表格行可选择同一工况，相关图表高亮，用户可查看该组模型。布局基于实际内容区域宽度自适应；聊天展开时图表区域变窄，优先保证单图可读，不强制多个窄图并排。

页面有两个可编排区域：ui.root 是左侧主区，ui.aside 是右侧 DSH 聊天窗下方的可选组件树，与 root 共用控件、数据、节点限制和工况联动。aside 可放表格、辅助图、已有图片或结论，不只限于表格。聊天收起或窄屏时，aside 自动移到主区下方。请统筹主区模型/主图高度与聊天窗高度，合理使用右侧下方空间，让两列内容长度大致协调；不把所有内容堆成长左栏，也不为了等高造图、重复结论。相关的响应图、偏差图、区间图优先放进同一个 tabs 面板切换，互补且需要同时比较时才并排。可以在 aside 使用 tabs 收纳数据表和解读。image:{file:真实工作区相对PNG/JPEG/WebP文件,alt:准确说明,caption?} 展示已有图片，不能为填版面虚构科学图或用不相关图片冒充结果。

ui 可以用 scope:overview 只编排研究总览，保留“模型”页独立可用；scope:model 只作用于模型页，省略则all。row/column/grid/tabs自由组合图、表、说明和已有model，操作项仍默认放显示设置。mode:replace 可替换适用区域的默认内容，避免重复一份固定总览。真实图表和表格都支持CSV，图表PNG保留图例与参考线。

controls:[{id:任意唯一字母开头ID,type:"number"|"range"|"toggle"|"select"|"color"|"text",label,unit?,group?,help?,default,min?,max?,step?,options?:[{value,label}]}]。ID 不需要前端预先注册。标签、单位、范围、分组和必要说明由你按当前需求组织，内容简短、面向使用者。controls 是完整列表：增加便捷操作时保留此前仍需要的基础项和参数组；不需要的组再删除。不要为了示范特定功能替换掉整套面板。

parameterValues:{任意已定义参数ID:值} 可在后续指令中只更新值，不必重新发模型或定义。宿主会保存用户手动调整的值并在下一次观察的 presentation.parameterValues 中返回；后续变更应复用这些值。替换 controls 可以删除旧参数、增加新参数。用户只是调整参数、颜色、视角或形状显示时不重新导出、不求解、不另写临时绘图脚本。

标题流程及执行过程属于 process-observer，只读，不属于 UI 操作插槽。计算子任务、网格、求解日志和保存场会独立推进这条流程。

parameters:[{title:分组名称,items:[{label:参数名,value:字符串,unit:单位字符串}]}]。条目可完全替换，按当前模型选取；请求中的值可标注在“任务设定”分组，不能冒充已核验值。

已有交付控件的兼容格式：controls:[{id,label,default?,min?,max?,step?,options?:[{value,label}]}]。兼容的基础 id 包括 cut(剖切开关)、cutAngle(0–180度)、mesh(线框)、scale(下拉 fixed/frame)、axialScale(0.08–1)、view(原始/重建视图下拉)。view 的 options 可省略，由实际交付视图自动生成；定制 value 只能使用实际视图 id 或 mesh/rod/sphere/shell 类型别名。摘要不含文件路径、工具名和数据格式，只写用户能理解的大节点。还可使用 cameraView(auto/3d/xy/xz/yz)、aspectMode(physical/fit，二维坐标展开时明确标注缩放)、displayMode(surface/slice)、sliceAxis(x/y/z)、slicePosition(0–1)、compare(布尔)、compareField(实际字段id)。默认提供观察方向；存在多个真实字段时可提供双变量比较；真实切片只适用于带内部拓扑的原始网格。只展示适用于当前模型的选项，没有结果时不要放色标选择。控件列表可替换，不写 HTML/JS。

exports:[{id,label,caseRoot,kind:"mesh"|"results",fields?:[字段及分量],time?:"latest"|"all"|逗号分隔的真实保存时刻,shape?:"mesh"|"rod"|"sphere"|"shell"|"revolve",axis?:"x"|"y"|"z",sweepAngle?:0到360的正数,radius?,innerRadius?,length?,radialBands?:[[内半径米,外半径米,径向格数]],timeUnit?:"s"}]，defaultView:已交付视图id。

facts.fieldFacts 给出当前实际保存帧的真实 min/max/uniform。若 T 或其他场 uniform:true，应明确说明保存场全域均匀，核对主任务的求解设定，不编造温度梯度，不用更换色标掩盖。真实数据范围与为了绘图避免零跨度扩展的色标范围不同。

网格已存在但无结果时，用 kind mesh。真实结果已存在时可请求 results；fields 仅选当前实际存在且用户关心的字段，向量/张量分量可写 D:x、sigma:principal_max。瞬态任务选择 time all。kind results 不代表求解已收敛，只表示展示已存在的保存场。

发布后在相同视口比较 model-column 与聊天栏最下方可见节点的底部。若两栏差距足以容纳一组次要图表，可整体移动该组页签到较短一侧，再用实际尺寸复查。模型与固定终态剖面可放在同侧，历史曲线和对应表格可放在另一侧。
